# UWB / アンカーとの関係

## このリポジトリでの役割

`Kenshin` はREDのコントローラー操作とSpresense姿勢角制御を管理します。UWB測距・アンカー通信プログラムはここには含めていません。

## 別の研究室UWBリポジトリについて

共有されたリポジトリ一覧では、次の構成が確認できます。

- Murata Type 2BP / SR150：`MURATA_Type_2BP/Raspberrypi_Multisession/version04.06.00/`
- セッション1〜5、Multisession、UART initiator / responder の各スクリプト
- Qorvo DW1000：別フォルダ
- Spresense_MultiIMU：別フォルダ

UWB用ソフトウェアが別リポジトリに存在することは確認できます。ただし、そのPrivateリポジトリのファイル本文をこちらから取得できなかったため、アンカーID、役割、実行引数、現在の実機との適合までは確認できていません。

## このProconリポジトリにない／未確認のもの

1. 実機で使用中の `DS_TWR_SR150_Multisession2.py` と依存ファイル一式。
2. タグと各アンカーのID・役割（initiator / responder）・セッション番号。
3. 全アンカーの電源・通信状態と、全アンカーから測距値が返ること。
4. アンカー座標、タグ高さ、座標系、測距ログ/CIRログの保存先。
5. UWB起動コマンドと停止・再起動手順。

2026-11-24のPiのUSB一覧では、UWB側のFTDIシリアルとSpresense側のCP2102Nシリアルが別々に認識されていました。これはUWB用インターフェースがPiに接続されていた証拠ですが、無線アンカー全台が動作している証拠ではありません。アンカーが無線接続なら、USB一覧にアンカー台数分のデバイスが出るとは限りません。

## 次回、実機で確認する最小項目

- `ls -l /dev/serial/by-id/` でUWBとSpresenseのUSBデバイスを区別。
- UWBのMultisessionプログラムを起動し、期待する全アンカーのIDから距離が継続して返るか確認。
- 1台ずつアンカーの電源を切り、該当IDの測距が消えるか確認。
- 取得CSVに時刻、アンカーID、距離、NLOS、RSSI等が記録されるか確認。

**結論：UWB用ソフトウェアの存在は確認できていますが、Kenshinの制御コードからアンカーを直接利用できる状態か、全アンカーが実際に測距できるかは未確認です。**

# 07 — 自動8ステップ旋回（45° × 8、60秒間隔）の導入条件と設計

2026-11-27。**構想・実装前**。現在の実機制御コードへ自動旋回を追加したわけではない。

## 目的

Proコンの専用操作を1回行うと、REDが同じ方向に45°ずつ8回旋回して、一周360°を完了する。各旋回開始時刻の間隔を**60秒**にする。初回旋回はボタン操作後すぐ、残りは60・120・180・240・300・360・420秒後を基本とする。

各停止後、Spresense P角度を使って45°の停止誤差を計算・表示。1回あたりの目標は **絶対誤差0.3°未満**。8回の累積360°誤差も別に評価する。

## 先に解決すべきこと

1. 現在の手動45°旋回の誤差がまだ0.3°を超えることが多い。まず既存プログラムの旋回制御を改善して、左右とも十分な反復試験で目標を満たすか確認する。
2. これまでの表示改善版は `Spresense P` の定期表示を抑えている。最初の受信Pを1度表示するよう段階1パッチを用意：`Spresense_v2/tools/patch_red_precision_stage1.py`。閾値を変えただけで精度達成を保証するものではない。
3. **現在のProコン送信はニュートラル状態でstopを連続送信する**。自動モード中にそのままstopを送ると1回目の旋回か待機が妨げられる。送信側・Pi側の両方を確認し、専用コマンドとkeepaliveの仕組みを追加する。
4. 現在の実機 `radicon_udp_server.py` の最新版全体とWindows `procon_send.py` は未回収。GitHubの旧コードで上書きしない。

## 実装する場合の安全仕様

- Proコンの実ボタン位置を `controller_check.py` などで検証してから、使われていない**専用ボタンの組合せ**に割り当てる。誤作動防止に長押し（例1秒）などを検討。
- 走行中でない、Spresenseのデータが新鮮、初期姿勢の安定を確認した場合だけ開始。
- 自動旋回の状態：`idle -> armed -> rotate -> settle -> wait -> rotate ... -> done`。**8回で自動終了**し、それ以上回さない。
- ボタン操作後もWindows送信側は有効なkeepaliveを一定間隔で送り続ける。**UDP通信途絶やSpresenseデータ異常時は即キャンセル・停止**。接続復帰しても自動再開しない。
- STOPボタン、手動操作、切断、Ctrl+Cで**即座に自動モードを解除**。
- 1回の旋回がタイムアウトした場合、途中で誤差が大きい場合や微修正が収束しない場合は次のステップを実行しない。
- ステップ開始の時刻とセンサP/誤差、微修正回数、キャンセル理由を記録。普段はCSVを自動作成しない。必要なら実験時のみログ。
- 0.3°を外れた場合の扱いは、当面 **安全停止して未達成と表示**を推奨。時間が経ったからといって勝手に次の旋回を始めない。
- 一周終了後も勝手に反復しない。再度ユーザーの明示操作が必要。
- **Spresense Pだけでは車体中心の位置が変わっていないことは保証できない**。

## 次回

1. 初期P表示・旋回微修正の段階1パッチを実験室で確認（既存制御ソフトのバックアップは必須）。
2. +45°、-45°を各数回測定してログを確認し、0.3°未満が安定して達成できるか判断。
3. 成功が安定してから、既存の `procon_send.py` に専用ボタン、既存の `radicon_udp_server.py` に8ステップ状態機械を追加する。新しい制御サーバーへ切り替えない。
4. まず車輪を浮かせて1ステップだけテストし、STOPと通信切断をチェック。次に2ステップ、最後に8ステップへ増やす。

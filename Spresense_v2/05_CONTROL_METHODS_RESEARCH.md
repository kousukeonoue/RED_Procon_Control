# 05 — 旋回・直進補正の仕組みと50cm自動移動への発展（調査メモ）

記録日: 2026-11-25。**現地で最新ファイルを確認する前の設計資料**。REDの実機コードを変更していない。

## A. 過去に実装した仕組み（確認できたソースと実験ログから）

### A1. Spresenseの角度の読み方
- 研究室版 `pospredict_bridge.py` をPiで起動し、TCP `127.0.0.1:5000` でデータを配信。Pi側ラジコンは `--imu` で利用。
- 送信テキスト `X:... Y:... Z:... R:... Y:... P:...` の **最後の `P`** が現在の旋回制御で使われている角度。
- 角度差は `(target - current + 180) % 360 - 180` のように折り返して比較。
- Spresense `P` に対する誤差と、Motiveの実yaw角に対する誤差は**別物**。いまだ実機での基準比較が不足。

### A2. 直進補正：方位保持（過去の実装の一例）
2026-11-23に取得されたコード断片の内容：
1. 前進・後退開始時に基準角 `hold_target = P` を記憶。押している間は基準を更新し続けない。
2. `e = wrap(hold_target - P)` を算出。
3. `correction = clamp(0.6 * e, -12, 12)` で左右出力差を作る。
4. 前進：`left=base-correction; right=base+correction`、後退は符号反転。
5. IMU通信切断・古いサンプル（>0.6秒）や角度が大きくずれた場合は停止。
2026-11-24のログで前進の通常PWM **48**、高速PWM **65** への変更を確認。最終実機での補正ゲインは**最新版ファイルで再確認**が必要。

### A3. 旋回：先読み停止＋停止後の微修正
2026-11-24の途中版ソース断片を確認：
- 開始角 `turn_start` と指定角（±5°/±45°）を記憶。
- `progress = wrap(P - turn_start) * direction`、`remaining=requested-progress`。
- `turn_rate` は角度差分÷サンプル間隔をローパス（`0.5*old+0.5*measured`）。
- 停止先読み：`lead = clamp(turn_rate * direction * 0.08, minLead, maxLead)`。45°程度ならリード2〜7°、5°なら0.8〜2.2°。
- PWM：5°は48、45°の場合、残り角度>18°なら51、>8°なら48、最後45。 `progress >= requested - lead` で `StopBrake(0.15)`。
- 停止約0.4秒後にPを再計測し、必要なら45PWMの約60msパルスを入れた版が存在。安全上、残差の範囲・パルス回数・改善しなければ中止するガードあり。
- 2026-11-24にはその後も短パルスの調整を複数回実施したが、**現在の最終版のパルス時間・試行回数はPiの最新ファイル未取得のため確定しない**。
- 途中ログでは残差+1.37°から一度のパルスで-1.45°に行き過ぎた例がある。最終的な評価はMotiveが必要。

## B. 改良の主眼

### B1. 旋回精度改善
1. Motiveを基準に `P` の符号・スケール・固定オフセット・ドリフトを確認（複数角度、左右、5/45/90度）。
2. `P` の角速度推定とモーター停止後の角度変化を記録し、`lead` の式（固定0.08s相当）を実測から調整する。
3. 粗旋回→低PWM→制動→静止0.4秒確認→必要なら**小さく一回ずつ**修正。最小パルスで大きく飛ぶなら、角度許容差を上げる／連打しない／パルスの機械的限界を認める。
4. 方向・角度ごとに行き過ぎ量を比較。飽和PWM、最低駆動PWM、摩擦、電池残量、床との接触を確認。
5. 角度誤差だけでなく、停止後角速度・機体位置の移動も記録。

### B2. 直進・後退の改善
1. 基準角を開始時に固定する。Motive yawを基準として、指令中の角度ずれと横ずれを測定。
2. 単純P補正が振動する場合、差分角速度によるD項・低域フィルタ・補正PWMの上限を検討。
3. 左右モーターの固定出力差があれば、モーター左右の基本PWM比を事前に調整（フィードフォワード）。前進と後退を別々に測定。
4. デッドゾーン（そもそも動き出すPWM）と速度をキャリブレーション。むやみに高ゲインにしない。
5. **方位保持だけでは横方向に滑った距離を直接回復できない**。UWB/Motiveで横ずれも見て評価し、後にライン追従を追加。

### B3. 十字キー↑/↓で50cm移動（未実装）
同時に使うもの：
- 角度保持コントローラ（上記B2）
- **移動距離を推定する機構**（モーター時間校正、車輪エンコーダ、UWB位置推定など）
- 目標までの残距離を使った減速・停止制御

状態の例：

```text
D-PAD UP / DOWN の新規押下
  → 進行方向 sign=+1/-1、開始時Pと開始時距離を記録
  → 向きを保持しながら直進/後退
  → 移動距離と残距離を更新
  → 目的地の手前でPWM/速度を下げる
  → 目標付近で停止
  → 静止後に最終距離と角度を評価
  → 大きく不足したときだけ安全な短い再補正（有効な距離計測が必要）
```

50cm移動指令では `target_s = +0.50 m`（前進）、`-0.50 m`（後退）。理想的には、開始位置 `(x0,y0)` と開始方位 `theta0` に対して：

```python
s = (x - x0)*cos(theta0) + (y - y0)*sin(theta0)  # 進行方向の移動量
cross = -(x - x0)*sin(theta0) + (y - y0)*cos(theta0)  # 横ずれ
err_distance = target_s - s
err_heading = wrap(theta0 - theta)
```

`x,y` は **UWBかMotive等、信頼できる位置ソース** から得る。Spresenseの表示位置 `X,Y,Z` をそのまま50cm制御に使って正確と仮定しない（単位・ドリフト検証が必要）。
また、距離は直線の絶対値だけでなく前後の**符号付き射影距離**を使う。後退中もロボット正面角は保つ。

### B4. 距離推定方式（正確性・実装負荷の比較）

| 方法 | 特徴 | 初手 |
|---|---|---|
| **時間×PWMの校正** | 追加ハードなし、すぐ試作可能。ただし床、電池、左右個体差、停止遅延で誤差 | 最初のオフライン基準作り |
| **UWB位置フィードバック** | 研究テーマに活用しやすい。ただし数cm規模の測位ノイズ・NLOS・遅延を補正する必要がある | 安定したアンカー環境で評価 |
| **車輪エンコーダ＋IMU** | 短距離制御に有利。追加機材が必要な場合もある。車輪の滑りで誤差が蓄積 | **既存REDにエンコーダがあるか確認**。存在すれば第一候補 |
| **エンコーダ＋IMU＋UWB** | 速い相対運動と絶対位置補正の両立を狙える。時刻同期・座標系・フィルタ設計が必要 | 最終的な改善案 |
| **Motiveの位置で閉ループ** | 実験室で高精度の基準制御を作れるが、Motive外では使えない | センサー・制御の性能上限測定 |

50cmの実測評価は **停止位置誤差[cm]、横ずれ[cm]、最終方位誤差[°]、10試行程度のばらつき、失敗数、停止までの時間**を記録。数値目標は基準実験の誤差を見て決定。
